веб-приложение "мессенджер"

## Быстрый старт

```bash
npm install
npm run dev
```

По умолчанию Vite поднимает dev-сервер на порту `3000`. Для production-сборки используйте `npm run build`, для локального предпросмотра — `npm run start`.

## Основные зависимости и инструменты

-   TypeScript (5.9.2) — проверка типизации: `npm run check:ts`
-   Vite (7.1.12) — сборка и dev-сервер (`npm run dev`, `npm run start`)
-   PostCSS (8.5.6)
-   Handlebars (4.7.8) — клиентская компиляция шаблонов
-   ESLint (9.35.0) — `npm run lint`, `npm run lint:fix`
-   Stylelint (16.24.0) — `npm run lint:css`, `npm run lint:css:fix`
-   Jest (29.7.0) с ts-jest (29.1.1) и jsdom (`jest.config.mjs`)
-   Husky (9.1.7) — git-hooks

Автодеплой настроен на Netlify из ветки `deploy`: https://lenaschat.netlify.app/

## Тестирование

-   Тесты написаны на Jest.
-   Запуск всех тестов: `npm test` (метчится по `*.test.*`).
-   Скрипт использует ключ Node `--experimental-vm-modules` для поддержки ES Module; предупреждение в консоли является ожидаемым.
-   Hook Husky (`.husky/pre-commit`) автоматически запускает проверки линтера и типизации перед коммитом.

## Валидация форм

Все поля форм проходят проверку (`npm run validation:test`):

-   `first_name`, `second_name` — латиница/кириллица, первая буква заглавная, без пробелов, цифр и спецсимволов (кроме дефиса).
-   `login` — 3–20 символов, латиница, возможны цифры (не только цифры), допускаются дефис и нижнее подчеркивание.
-   `email` — латиница, могут быть цифры и `-`, `_`; обязательны `@` и точка с буквами перед ней.
-   `password` — 8–40 символов, минимум одна заглавная буква и цифра.
-   `phone` — 10–15 символов, только цифры, возможен ведущий `+`.
-   `message` — не пустая строка.

## Маршруты приложения

Роутер определяется в `src/app.ts` и рендерит следующие экраны:

-   `/` — авторизация (`LoginPage`)
-   `/sign-up` — регистрация (`RegisterPage`)
-   `/settings` — профиль пользователя (`ProfilePage`)
-   `/messenger` — список чатов и история сообщений (`ChatsPage`)
-   `/404` — страница «не найдено»
-   `/fatal` — экран критической ошибки

Маршруты переключаются без перезагрузки страницы через кастомный `Router`, основанный на `history.pushState`.

## Основная функциональность

-   Регистрация и авторизация, управление сессией и редиректами после успешного входа/выхода.
-   Просмотр и редактирование профиля: обновление полей, смена пароля, загрузка аватара.
-   Работа с чатом: отображение списка, создание и удаление чатов, выделение активного.
-   Управление участниками выбранного чата (добавление/удаление по логину) через `chatController`.
-   Отправка и получение сообщений по WebSocket: первое подключение подгружает историю, новые сообщения отображаются в `ChatHistory` с разделителями дат.
-   Хранение данных в типизированном сторе (`Store` на базе `EventBus`), контроллеры инкапсулируют обращения к API.

## Работа с API

Сетевой слой находится в `src/api` и построен на базовом `HTTPTransport` (см. `src/api/base.ts`). Поверх него реализованы следующие классы:

-   `AuthApi` (`src/api/auth.ts`) — регистрация, авторизация, выход и получение текущей сессии.
-   `UserApi` (`src/api/user.ts`) — изменение данных профиля, смена пароля и обновление аватара.
-   `ChatApi` (`src/api/chat.ts`) — создание/удаление чатов, управление участниками, получение токена для WebSocket.
-   `ResourceApi` (`src/api/resource.ts`) — работа со статическими ресурсами (загрузка и получение файлов).
-   `Socket` (`src/api/socket.ts`) — обертка над WebSocket: пинг, запрос истории, доставка новых сообщений.
-   `ErrorWithCode`, `handleError`, `throwError` (`src/api/error.ts`) — единая обработка ошибок.

Контроллеры в `src/controllers` инкапсулируют бизнес-логику и обновляют `store`, обеспечивая взаимодействие компонент с API.
